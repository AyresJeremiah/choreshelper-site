Self-hosting quick start

Run a ChoresHelper server on a Raspberry Pi or any small Linux machine on your home network.

What you need

  • A 64-bit Linux machine (Raspberry Pi 4 or 5 with 4 GB or more, or any amd64 or arm64 box) on your home network. An SSD is better than an SD card for the database.
  • Docker Engine with the Compose plugin.
  • A fixed LAN address for the server, such as 192.168.1.50 (reserve it in your router).

1. Create a folder and the files

mkdir -p ~/choreshelper && cd ~/choreshelper

Create .env (replace the values):

# The server's LAN IP address, as devices will reach it
CHORES_HOSTNAME=192.168.1.50
# Which release to run
API_VERSION=0.8.0
POSTGRES_PASSWORD=change-me-use-openssl-rand-base64-24
HOUSEHOLD_NAME=Our Household
HOUSEHOLD_TIMEZONE=America/Chicago

# First run only: creates the first admin account
SETUP_INITIAL_ADMIN_USERNAME=admin
SETUP_INITIAL_ADMIN_PASSWORD=choose-a-real-password

Create Caddyfile. Caddy provides HTTPS using its own local certificate authority, with no internet needed:

{
	default_sni {$CHORES_HOSTNAME}
}

{$CHORES_HOSTNAME} {
	tls internal
	encode zstd gzip
	reverse_proxy api:8080 {
		header_up X-Forwarded-Host {host}
	}
}

Create docker-compose.yml:

services:
  postgres:
    image: postgres:17-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: choreshelper
      POSTGRES_USER: choreshelper
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set in .env}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U choreshelper"]
      interval: 5s
      timeout: 5s
      retries: 10

  api:
    image: ghcr.io/ayresjeremiah/choreshelper-api:${API_VERSION}
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      ASPNETCORE_ENVIRONMENT: Production
      ASPNETCORE_FORWARDEDHEADERS_ENABLED: "true"
      Identity__Issuer: "https://${CHORES_HOSTNAME}"
      ConnectionStrings__Chores: "Host=postgres;Port=5432;Database=choreshelper;Username=choreshelper;Password=${POSTGRES_PASSWORD}"
      Database__MigrateOnStartup: "true"
      Household__Name: ${HOUSEHOLD_NAME:-ChoresHelper}
      Household__TimeZone: ${HOUSEHOLD_TIMEZONE:-America/Chicago}
      Setup__InitialAdminUsername: ${SETUP_INITIAL_ADMIN_USERNAME:-}
      Setup__InitialAdminPassword: ${SETUP_INITIAL_ADMIN_PASSWORD:-}
      Discovery__Enabled: "false"

  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    depends_on:
      - api
    environment:
      CHORES_HOSTNAME: ${CHORES_HOSTNAME}
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config

volumes:
  pgdata:
  caddy_data:
  caddy_config:
Keep the caddy_data volume. It holds the server's certificate. If you delete it, devices will see a new certificate and need to reconnect.

2. Start it

docker compose up -d
docker compose ps
curl -k https://192.168.1.50/api/info

The first start creates the database and runs migrations. Once /api/info responds, the server is ready.

3. First admin account

A fresh install has no accounts. On its first start with an empty database, the server creates one admin from SETUP_INITIAL_ADMIN_USERNAME and SETUP_INITIAL_ADMIN_PASSWORD. After that these values are ignored. Sign in at https://<server-ip> in a browser (accept the one-time certificate warning), change the password, add your household members and their accounts, then remove the two SETUP_ lines from .env so no password sits on disk.

4. Connect the app

Install the ChoresHelper app, join the same Wi-Fi, enter the server's IP address and confirm the certificate fingerprint on first connect. More in Support.

Updating and backups

  • Update: set a new API_VERSION in .env, then docker compose pull && docker compose up -d. Migrations apply on start.
  • Back up the database regularly, for example: docker compose exec postgres pg_dump -Fc -U choreshelper choreshelper > backup.dump. Copy the file somewhere off the server.

Security notes

  • Do not expose the server to the internet. It is designed for a trusted home network.
  • Postgres is not published outside the Compose network.
  • Use strong, unique passwords and keep the host updated.
